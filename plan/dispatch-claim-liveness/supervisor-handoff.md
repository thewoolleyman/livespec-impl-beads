## Decision-vetting rubric

Escalate ONLY decisions that are BOTH genuinely blocking AND genuinely
human-facing. For this thread that means: **the groom's slice cut and acceptance
criteria** (the maintainer owns every cut); **whether requirement 3's bound is a
lease or is subsumed by requirement 1**; **whether the design elects new lifecycle
vocabulary or a lease semantic**, which escalates to core `livespec` and is
spec-ratification-tier; **how to sequence against the two pending spec proposals**;
and billing/account choices.

Everything else: have the worker PREPARE the decision — evidence assembled,
options cut, recommendation named — then surface the FINISHED question, not the
raw problem.

A supervisor MAY discharge an acceptance leg itself when it has INDEPENDENTLY
verified the evidence against the forge (merged PR ancestry, live exercise where
possible) and records the basis in the close reason.

### No idle, no silent block

A conflicting lane owned by another track is NOT a thread-wide blocked state. If
some action is owned elsewhere: (1) stand down on that action only; (2) enumerate
the remaining non-conflicting work; (3) drive the next concrete safe action
immediately; (4) only if NO legitimate non-conflicting action exists, raise ONE
maintainer-facing blocking question with the recommended answer first.

If the worker is genuinely gated, confirm a `blocked:` marker exists at
`tmp/overseer/dispatch-claim-liveness/.overseer-state` naming the concrete pending
decisions, and that it is REMOVED when work resumes. Verify the file, do not
accept the claim — a sibling track reported that marker as live at three moments
when the file did not exist.

## Standing safety clauses

Repeat these in every instruction sent to the supervised session:

- Never pass `--no-verify`; **halt and report on hook failure** rather than working
  around it.
- Never touch another session's worktrees or branches.
- Every tracked-file change goes **worktree → PR → rebase-merge → cleanup**; never

  `mise exec -- git commit/push` so the hooks actually run.
- Verify against the FORGE (`origin/master` after a fetch), never a working tree
  that may be stale. "Absent from my working tree" is evidence of nothing.
- Establish outcomes from **artifacts** (merged PR / ledger / journal), never exit

- Prefix `bd` with `/usr/local/bin/with-livespec-env.sh --`. Batch ledger reads; do
  not narrate into the ledger.

For any factory dispatch: prove container ownership by **run-config argv via an
ALL-container scan** — never by image shape, position, or timing; and treat
`exit 137` as **ambiguous** between a kill and normal teardown, never as
kill-proof.

  question.** This supervisor read the worker's interim scratchpad prep at its
